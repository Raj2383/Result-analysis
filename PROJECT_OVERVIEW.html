GGSIPU Result Analyzer & CGPA Calculator — Project Overview

Faculty uploads one result PDF · Students look up by enrollment number + semester (no student login) · Toppers & analytics included

1. Architecture

Monorepo, three layers. All traffic flows through a versioned REST API; the client never touches the database.

client/ (Vite React) ── Axios + httpOnly cookie ──▶ server/ (Express, /api/v1) ── pg Pool ──▶ PostgreSQL
                                                            │
                                                  pdfjs-dist │ transactional ingest
                                                            ▼
                                              parsers → services → repositories → tables

Backend layering (strict)

LayerFolderRule
Routessrc/routes/URL + middleware chain (auth, requireRole, validate, upload) only
Controllerssrc/controllers/Thin: request → service → apiResponse. No SQL, no business rules
Servicessrc/services/Business logic + transactions (auth, ingestion, results, toppers, analytics)
Repositoriessrc/repositories/ALL SQL lives here, parameterized only, one file per domain
Parserssrc/parsers/Pure text → structured data. No I/O
Utilssrc/utils/Shared helpers (ApiError, apiResponse, calculations, rollNumber, hash, pagination, rankingSql)

Consistent response shape: { success, data, message }. All errors thrown as ApiError, formatted by one central handler.

Frontend (feature-based)

app/ (router, providers) → pages/ → features/{auth, upload, student, toppers, analytics} (each with api/, hooks/, components/) → shared components/ui/ primitives (one Table shared by marks + toppers). Data fetching only via TanStack Query inside feature hooks.

3. PDF extraction approach

GGSIPU PDFs alternate Scheme pages (institution + paper table) and Result pages (exam header + student blocks).

PDF bytes → extractText (pdfjs, per-page lines) → parseResultText (state machine)
→ ingestPdf (SHA-256 dedupe → one transaction of batched upserts → recompute summaries)
  • Line reconstruction: pdfjs returns positioned fragments; cluster by y (±2 units), sort top-down / left-to-right.
  • Line matchers: one regex per type — institution, SchemeID, Sem./Year, exam header (REGULAR|REAPPEAR), student header (11-digit roll, name until SID:), paper entry 020301(4), scores (internal -, external A = absent), totals (84(A+), grace 40(P)*, A(F)), scheme paper rows (minor -- → null).
  • State machine: walks lines with carried institution/scheme/exam context. Never crashes on bad lines (warns, max 50, returned with the upload). Credits-secured (incl. 0) distinguished from page footers by forward-scan + credit-sum range, first-wins.
  • Ingestion: SHA-256 → 409 on re-upload; one transaction of batched INSERT … ON CONFLICT DO UPDATE upserts (incl. UNLISTED stubs for result-only papers); SGPA/CGPA/ranks recomputed pre-COMMIT.

Calculation rules (single source: utils/calculations.js): SGPA = Σ(credits×gp)/Σ(credits), fails/absent = 0, 2-decimal rounding; reappear = latest attempt per paper; CGPA = Σ(SGPA×credits)/Σ(credits); backlog = any F/absent in latest attempts.
